# AdSense 審査・ads.txt 運用メモ（fp-master.jp）

Google AdSense の合格と、ads.txt の「不明」表示への対処をまとめる。対象ドメインは
`fp-master.jp`（GitHub Pages + カスタムドメイン、ビルド出力は `public_site/`）。

---

## 1. ads.txt が「不明」になる理由と対処

### 結論：ファイル自体は正しい

ルートの `ads.txt` はビルドで `tools/write_ads_txt.py` が `site-config.json` の
`adsenseClientId` から生成し、`public_site/ads.txt` に配置している。内容は AdSense 公式形式：

```
google.com, pub-7927260139193410, DIRECT, f08c47fec0942fa0
OWNERDOMAIN=fp-master.jp
```

- `pub-7927260139193410` … 発行者 ID（`ca-pub-` を除いた形）。管理画面の値と一致。
- `f08c47fec0942fa0` … Google の認証局 ID（固定値）。
- `OWNERDOMAIN=fp-master.jp` … ルートドメインの明示（サブドメイン運用時の取り違え防止）。

### 「不明（Unknown）」の意味

AdSense の ads.txt ステータスは主に **承認済み / 見つかりません / 不明** の 3 種類。
**「不明」は「ファイルが間違っている」という意味ではない**。多くは次のいずれか：

1. **サイトがまだ審査通過していない／広告配信が始まっていない。**
   AdSense は広告を配信しているサイトの ads.txt を定期クロールして「承認済み」に更新する。
   未承認・未配信のうちはクロール優先度が低く、「不明」のまま据え置かれやすい。
   → **本質的な対処はサイトの審査通過**（= 第 2 章のコンテンツ対策）。承認後、数日〜数週間の
   クロールで自動的に「承認済み」へ変わる。
2. **クローラがファイルに到達できていない。** 次の順で潰す。

### 到達性チェックリスト

- [ ] `https://fp-master.jp/ads.txt` が **200** で返り、上記テキストがそのまま表示される
      （HTML やエラーページにリダイレクトされない）。
- [ ] `www.fp-master.jp` を使う導線がある場合、`https://www.fp-master.jp/ads.txt` も
      到達できる（apex と www の両方をカバーする DNS/リダイレクト設定になっているか）。
      AdSense はアカウントに紐づくホスト名で ads.txt を探す。
- [ ] `robots.txt` が ads.txt を拒否していない（現状は許可済み。下記参照）。
- [ ] HTTPS が有効で証明書が正常（GitHub Pages の「Enforce HTTPS」ON）。
- [ ] 独自の CDN やリバースプロキシを挟んでいる場合、`/ads.txt` をキャッシュ・改変していない。

`robots.txt`（`public_site/robots.txt`）は ads.txt クローラを明示的に許可している：

```
User-agent: Google-adstxt
Allow: /ads.txt

User-agent: *
Allow: /
```

### やること

1. まず**サイト審査を通す**（第 2 章）。ads.txt「不明」の大半はこれで解決する。
2. 上記到達性チェックを 1 つずつ確認する。
3. 直った後も反映まで時間差があるため、**数日〜数週間は様子見**。管理画面の再確認を急がない。

## 2. 「有用性の低いコンテンツ」で落とさないための対策

AdSense の不承認理由で最も多いのが **「有用性の低いコンテンツ（Low value content）」** と
**「スケーリングされたコンテンツ（Scaled content abuse）」**。本サイトは自動生成ページが多く、
ここが最大のリスク。

### 現状の構成（サイトマップ 1,194 URL）とデータ実測

ソース CSV を実測した結果、**「解説が空・定型だけの薄いページ」は実際には存在しなかった**。

| 種別 | サイトマップ登録数 | 品質の実測 | リスク |
| --- | --- | --- | --- |
| 過去問 `q/past/**` | 150 | `past_questions.csv` 150 問すべてに解説あり（結合 41 字以上、中央値 107 字） | 低〜中 |
| 実践演習 `q/practice/**` | 651 | `practice_questions.csv` 650 問すべて結合 121 字以上の解説 | 低〜中 |
| 一問一答 `q/ichimon/**` | 索引のみ | 詳細 90 ページは既に noindex（索引だけ登録） | – |
| 用語解説 `terms/g-*` | 約 280 | 定義・根拠・誤解・覚え方・FAQ の構造化テンプレ | 中 |
| 試験ガイド `articles/*` | 105 | 読み物として本文量あり | 低 |
| 固定ページ | 数点 | about / privacy / contact | – |

結論：**大量 noindex は正当なコンテンツと流入を捨てるため不適切**。残る実質的な課題は、
CSV に肢別解説が無い問題で自動生成される「誤答肢の注記」が、正答の再掲などで
**水増しに見えていた**こと。

### 実施済みのアクション

#### 済：連絡導線の修復
- `/contact`（`contact.html`）を新設。従来フッターの `https://fp-master.jp/contact` は
  ページ不在で 404 だった。問い合わせ手段（Google フォーム）・運営者情報・対応範囲を明記。
  → 審査で見られる「運営者への連絡手段」を満たす。

#### 済：過去問・実践演習の解説から定型の水増しを除去
- `tools/q_explanation.py` の誤答肢注記フォールバックから、リード文と重複する正答の再掲
  （`本問で選ぶべき正答は（N）「…」です。この肢の記述は、その論点とは一致しません。`）と、
  全肢に付く定型指示（`誤答肢との差分を一行メモに残してください。`）を削除。
  代わりに解説本文（正答の根拠）をより長く表示するようにした。
- 効果：定型フィラー 2 種が全 q ページから消滅。独自本文の密度が上がり、
  「自動生成・水増し」に見える度合いを低減（該当 43 ページを再生成）。独自コンテンツは削っていない。

### 今後の任意改善（非必須）

- 各問の解説をさらに厚くしたい場合は、ソース CSV の `explanation_choices` 列に
  肢別の理由を入れる（フォールバックより CSV が優先される）。
- 計算問題など解説が短い問題（例 `q/practice/p035` の PER 計算）は、短くても
  完結しているため対応不要。
